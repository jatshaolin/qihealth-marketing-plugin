# Ad Learnings — Aprendizaje acumulado de iteraciones

Archivo vivo donde el sistema acumula los patrones que funcionan y no funcionan en QiHealth, sub-segmento por sub-segmento. Cada vez que se itera un anuncio, el resultado se anota aquí. A los 60-90 días, este archivo es un activo único de QiHealth — la "voz colectiva" de qué convierte para esta marca específica.

## Estado al inicio del MVP

Vacío. Se llena con cada iteración real.

---

## Estructura de cada entrada

Cada entrada se etiqueta por sub-segmento + plataforma + formato + etapa funnel.

```markdown
### [Fecha] — [Sub-segmento] — [Plataforma] — [Formato] — [Etapa]

**Pieza original**: [link o referencia]
**Hipótesis original**: ...
**Performance**:
- CTR: ...
- CPM/CPC: ...
- Conversión: ...
- Veredicto: Winner / Maybe / Loser / Fatiga

**Feedback recibido**: ...
**Iteración aplicada**: ...
**Performance post-iteración**:
- ...

**Aprendizaje extraído**: 
- ...

**Tag para biblioteca**: [keyword para futuras búsquedas, ej: "hook-pregunta", "casting-medico", "voice-emocional"]
```

---

## Categorías de aprendizaje

A medida que se acumulan iteraciones, los aprendizajes se categorizan en:

### A. Hooks que funcionan / no funcionan
Por sub-segmento. Patrones de los primeros 3 segundos que generan o destruyen retention.

### B. Estructuras narrativas
Problema-revelación-CTA / Comparativa / Testimonial / Educativo puro. Cuál convierte mejor para cada sub-segmento.

### C. Casting y voice
Médico vs paciente vs voiceover anónimo vs animación. Tono clínico vs cálido vs introspectivo.

### D. CTAs
Texto literal del CTA + posicionamiento (final del Reel vs middle vs overlay continuo).

### E. Visuales
Color, tipografía, B-roll generado vs filming real, on-screen text density.

### F. Plataforma específica
Lo que funciona en TikTok no necesariamente en IG ni viceversa. Aprendizajes por canal.

### G. Audiencia específica (paid)
Cuáles audiencias Meta/TikTok funcionaron. Lookalikes que escalaron. Detailed targeting que sobrevivió a Andromeda.

---

## Output del archivo en producción

Cada vez que el orquestador o una persona produce un anuncio nuevo, consulta este archivo para:

1. Buscar patrones ganadores en el mismo sub-segmento + formato + etapa
2. Evitar repetir patrones marcados como perdedores
3. Aplicar voice y casting que ha funcionado históricamente
4. Heredar CTAs y estructuras probadas

A los 30 días, este archivo debe tener al menos 50-80 entradas reales de iteraciones.

A los 90 días, debe ser el moat creativo de QiHealth: ningún competidor tiene este aprendizaje específico para tu marca y tus sub-segmentos.

---

## Reglas para mantener este archivo limpio

- Solo iteraciones con data real (no especulación)
- Cada entrada debe tener performance concreta (CTR, CPM, conversión)
- Aprendizajes en lenguaje accionable, no descripciones genéricas
- Si una entrada se vuelve obsoleta (cambió Andromeda, cambió audiencia, cambió producto), se marca como `[OBSOLETO yyyy-mm-dd]` pero no se borra (histórico vale)
- Cuando se acumulen >100 entradas, se hace consolidación trimestral en patrones gruesos

---

## Plantilla rápida para anotación manual

Si el equipo (Jose, Performance Manager, Community) quiere anotar manualmente un aprendizaje fuera del flujo automático, usar este formato corto:

```
[Fecha] | [Sub-seg] | [Plataforma] | [Lo que aprendí]
```

Ejemplo:
```
2026-05-12 | Legacy | IG Reels | Hook que abre con voz del padre del usuario funciona 3x mejor que voiceover anónimo
```

Estos quedan al final del archivo y se procesan en el batch trimestral para integrarse a las categorías formales.
